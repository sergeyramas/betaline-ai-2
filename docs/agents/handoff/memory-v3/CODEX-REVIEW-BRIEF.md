## Задание (текст промпта для Codex)

Ты — адверсариальный ревьюер архитектуры. Твоя цель — **сломать** предложенный план единой памяти для парка
агентов (Mac + три VPS + RamOS + облачные сессии Claude Code Remote), а не одобрить его.
Оптимизм не нужен; нужны конкретные сценарии отказа и что с ними делать.

Прочитай, в этом порядке, прямо из репозитория:
1. `wiki/journal/2026-09-22-memory-v3-decision.md` — сам план (объект ревью).
2. `wiki/projects/karpathy-vault/2026-05-01-memory-architecture-design.md` — предыдущая спека v2, которая умерла молча.
3. `wiki/projects/karpathy-vault/MEMORY.md` — история двухконтурной памяти и грабли хуков.
4. `wiki/journal/2026-05-11-handoff-agent-coordination-system.md` — как строили fleet-ledger и объединяли vault'ы.
5. `CLAUDE.md` в корне vault — контракт LLM-Wiki, который план обязан не нарушить.
6. `scripts/hooks/jarvis-git-sync-*.sh` — существующие хуки синхронизации.

Факты для калибровки (из аудита 22.09): ledger agent-fleet — 18 002 события, 86 % START без DONE, 56 % без slug;
vault не коммитился с 05.09; VPS за 4 месяца сделали 1 коммит в vault; автосинк на Mac стоял с 09.08 до 02.09;
05.09 из vault удаляли учётные данные ATI.

Атакуй как минимум эти направления и по каждому дай вердикт:

1. **Модель конфликтов.** «У хоста свой каталог событий, общие страницы правит человек или MCP» — где это
   ломается? Два агента на одном хосте одновременно; человек в Obsidian правит страницу, пока MCP её же
   обновляет из jarvis-assistant; rebase --autostash с незакоммиченными правками Obsidian; переименования файлов.
2. **Единый писатель на hermes.** Что происходит, когда hermes недоступен час / сутки / неделю? Описанная
   деградация «в локальный git» — реально ли агент об этом узнает и не потеряет ли `remember`?
   Очередь и повтор — где они?
3. **Отказ от iCloud.** Риски переноса vault из iCloud-пути в `~/Jarvis`: Obsidian-плагины, iPhone,
   Web Clipper пишет в `raw/web-clipped/` — куда он будет писать после переезда? Что теряется.
4. **Секреты.** rclone-токен Google Drive на hermes, Bearer-токен MCP в `~/.claude.json` на каждой машине и
   в конфигурации облачной сессии, gitleaks в pre-commit — достаточно ли? Какой минимальный blast radius при
   компрометации hermes?
5. **MCP по публичному интернету.** streamable-HTTP за nginx с Bearer — что ещё нужно (rate limit, IP allowlist
   через Tailscale, mTLS)? Стоит ли ставить сервер в Tailscale-сеть и не открывать наружу вообще; тогда как
   подключается облачная сессия, у которой Tailscale нет?
6. **Рост.** События файлами: сколько файлов через год при текущем темпе (~60 сессий/день)? Когда git-операции и
   ripgrep станут медленными, что с `context()` ≤ 4k токенов при разросшихся index.md?
7. **Молчаливая смерть.** v2 умерла, потому что никто не заметил. Достаточно ли доктора из §5? Какие отказы
   он НЕ поймает? Предложи минимальный набор проверок, который ловит ровно те три отказа, что убили v2.
8. **Порядок внедрения.** Правильно ли начинать с Mac/iCloud (шаг 1), а не с MCP? Есть ли шаг, который
   нельзя откатить?
9. **Альтернативы.** Сравни с: Syncthing между хостами без GitHub-хаба; Obsidian Sync как транспорт;
   БД-первый дизайн (PocketBase/SQLite как источник правды, markdown — экспорт); чистый «git + хуки» без MCP.
   Для каждой — одна причина, почему она лучше, и одна, почему хуже, чем план.
10. **Стоимость владения.** Сколько компонентов нужно поддерживать (демоны, cron, MCP, rclone, доктор) и что из
    этого можно выкинуть без потери трёх свойств из §2 плана.

## Формат ответа (строго)

Markdown-страница с frontmatter:

```
---
title: "Codex-ревью Memory v3"
type: review
created: <дата>
verdict: <GO | GO-WITH-CHANGES | NO-GO>
---
```

Затем разделы **1–10** ровно в порядке выше. В каждом:
- **Вердикт:** OK / RISK / BLOCKER
- **Сценарий отказа:** конкретный, воспроизводимый (кто, что делает, что ломается)
- **Исправление:** одно-два предложения, что изменить в плане

В конце — **«Топ-3 правки, без которых не стартовать»** и **«Что из плана выкинуть»**.
Не пересказывай план. Не хвали. Если направление действительно закрыто — так и напиши «OK» в одну строку.
